# Ran Jin · Zhejiang University 个人网站

一个中文个人网站，采用米白、深绿与暖橙配色，包含原创 SVG 插画、个人介绍、作品筛选与详情、GitHub 联系入口和主页链接分享。适配手机、平板和电脑；无需服务器数据库、账号或 API 密钥。

## 裙期 · Lolita 尾款与小裙子手账

从个人空间导航中的 **裙期手账** 或作品卡片打开。开发路径为 `/lolita/`，GitHub Pages 路径为 `/jinran0210ye/lolita/`。

- 记录裙名、店铺、颜色尺码、订单号、定金金额与支付日期、尾款金额和备注；尾款可以留空待确认或标记为预估。
- 设置预计补款的起止日期及提前 0、1、3、7、14、30 天提醒。网页区分等待、即将开始、正在补款、超过预计时间和时间待定；时间范围以商家公告为准。
- 分别上传最多 3 张裙图与 3 张定金凭证，支持 JPG、PNG、WebP，原图不超过 10 MB，压缩后本地保存。随时可以编辑、增删和放大查看图片。
- 汇总待补金额、正在补款金额、未来 30 天范围内的金额和已付定金；未知尾款单独计数，取消和已付订单不计入待补。
- **已补尾款** 时填写实际金额和日期，自动收入 **已购买的小裙子** 清单。每条裙子的总价为“已付定金 + 实付尾款”，已购清单汇总数量、总花费、定金和实付尾款；不含未录入的其他费用。
- 支持关键词、状态、月份筛选和排序、分页展开、编辑、删除撤销、只读示例，以及包含全部订单与图片的 JSON 备份合并或替换恢复。
- 导出单笔或全部已设置日期的待补订单为 `.ics` 日历。每笔生成覆盖预计日期范围的全天事件，并附带开始前及结束当天北京时间上午 9 点的提醒。提醒是否生效由导入的日历应用设置决定。网页关闭后不自行推送；用户已选择网页与手机日历提醒。

订单和图片保存在独立的浏览器 **IndexedDB** 数据库 `ran-jin-lolita:v1`，不上传服务器或 GitHub，不与记账和人生记录合并。无需服务器数据库或凭据。换设备、换浏览器、使用无痕模式或清理网站数据前，请导出 JSON 备份；压缩图不能替代原始付款凭证的备份。同一浏览器账户的使用者可以访问这些记录，此手账没有密码加密。

日历是导出时的快照，不会自动同步；更改日期、取消或补完尾款后，需要在手机日历中移除旧提醒，必要时重新导出。每份手账最多 500 笔订单，全部内容最多约 25 MB 字符量；存储空间还受浏览器配额影响，保存失败不会覆盖已有记录。数据库使用读写事务检查编辑冲突，支持跨标签页刷新。

页面在 `lolita/index.html`，逻辑在 `src/lolita/`，测试在 `tests/lolita.test.js`。`npm test` 验证金额、状态、日期范围、已购总价、备份和日历格式；使用全新浏览器上下文检查实际上传、持久化、付款入衣橱、日历下载与备份恢复，不触碰真实用户的数据。

## 人生大事记录

从个人空间导航或作品卡片中的 **人生大事** 打开。开发页面路径为 `/life/`，GitHub Pages 页面路径为 `/jinran0210ye/life/`。

- 按年份整理学习、事业、关系、旅行、成长及其他重要时刻。
- 记录标题、日期、地点、故事与一张照片；支持编辑、重要标记、移除及撤销。
- 按年份、分类、关键词、重要标记筛选，支持正反时间顺序和加载更多。
- 可选择每年纪念，显示最近纪念日与倒计时；2 月 29 日在平年按 2 月 28 日计算。提醒仅显示在页面中。
- 照片支持 JPG、PNG、WebP，原图小于 10 MB，自动压缩为 JPEG 后保存在本地。
- JSON 备份包含全部记录及照片，可合并或替换恢复；相同编号保留当前版本，重复导入不会重复添加。

这是用户选择的 **私人记录版本**：真实记录与照片只保存在当前浏览器，不会上传到公开网站、服务器或 GitHub。其他访客使用的是自己的记录。记录与记账工具使用独立存储，互不覆盖。示例时间线只读，明确标注为示例，不代表 Ran Jin 的经历，也不会写入真实数据。

更换设备、浏览器或网址，使用无痕窗口或清除网站数据时，请先导出备份，再在新浏览器中导入。每个档案最多 500 条记录，照片与故事的总量受本地存储空间限制；保存失败时保留原数据并显示错误。同一浏览器账户的使用者可能访问这些记录，因此此版本不是加密保险箱或云同步服务。

页面在 `life/index.html`，逻辑在 `src/life/`，自动测试在 `tests/life.test.js`。`npm test` 同时验证记账与人生记录的日期、统计、备份和存储处理；Vite 会构建个人空间、记账、人生记录与裙期手账四个页面。

## 轻记账

从个人网站导航中的 **轻记账** 打开工具。开发服务中的页面路径为 `/ledger/`；Pages 发布构建中的页面路径为 `/jinran0210ye/ledger/`。

- 以人民币记录收入和支出，可设置分类、账户、日期与备注。
- 编辑记录、删除并撤销；按月份、收支类型、分类和关键词筛选，支持金额及日期排序与分页。
- 月度收入、支出、结余、分类分布和六个月趋势；按月份设置预算并提示超支。
- 数据自动保存在当前浏览器，刷新后保留；支持其他窗口的更新，并检查编辑冲突。
- **体验示例** 使用独立、只读的示例账本，不写入真实数据。
- **导出 JSON 备份** 包含所有月份的记录与预算；导入可选择合并或替换，默认合并并保留已有编号的记录与预算。
- **导出当前明细 CSV** 导出当前月份和筛选结果，适合在表格软件中查看；CSV 不用于恢复账本。

### 秘密基地

点击轻记账左上角的 **小账本图标** 进入，首次使用时设置至少 8 个字符的独立密码。秘密基地复用记账、编辑、筛选、预算与图表功能，使用单独的本地存储；记录、预算、统计和备份均不计入普通总账，也不会上传到 GitHub 或服务器。普通账本的现有数据无需迁移。

- 记录以 AES-GCM 256 位加密保存，密码通过 PBKDF2-SHA-256（310,000 次、随机盐）派生密钥，每次保存使用新的随机 IV；密码与解密后的记录不会写入本地存储。
- 点击“锁定并返回总账”、刷新、切到后台或 5 分钟未操作时锁定；密码只用于当前解锁，不保存到网站。
- 秘密基地只导出 **加密 JSON 备份**，不提供明文 CSV。解锁后可合并或替换加密备份，需要输入该备份的密码。普通账本拒绝导入秘密备份。
- 换浏览器时，可从入口的“从加密备份恢复”使用备份原密码恢复；已有秘密基地时，替换前需要勾选确认，并可先“保存现有加密数据”。数据损坏时也可以先保存原始加密数据，不会被空账本覆盖。
- 密码遗失无法找回。请妥善保存密码和加密备份；清除浏览器数据会删除本地秘密基地。加密保护存储与备份，解锁期间请注意屏幕隐私。

实现位于 `src/ledger/secret.js`，测试覆盖总账隔离、加密恢复、错误密码、数据篡改、并发保存冲突、锁定中断与存储失败。

这不是云同步账本。更换设备、浏览器或网站地址，使用无痕窗口或清除网站数据，都会影响本地数据的访问；请定期导出 JSON 备份并妥善保存。其他访客看到的是他们各自的账本，数据不会随网站代码上传或公开。金额以整数“分”累计，本月结余是收入减去支出，不是银行账户余额。

记账逻辑在 `src/ledger/`，页面在 `ledger/index.html`。运行自动测试：

```sh
npm test
```

测试覆盖金额精度、日期、统计、筛选排序、备份验证、重复导入、CSV 公式防护和存储失败。GitHub Pages 工作流会先运行这些测试，再构建和部署四个页面。

## 本地运行

需要 Node.js 22.12 或更新版本（云环境已验证 Node.js 24）。

```sh
cd /workspace/jinran0210ye # 本地电脑请改为实际项目目录
npm ci
npm run dev
```

开发服务使用 5173 端口，支持修改后的自动更新。`.npmrc` 将 npm 缓存放在项目内的 `.npm-cache/`，适用于云环境，缓存不会提交到 Git。

```sh
npm run build
npm run preview
```

构建产物在 `dist/`；预览服务使用 4173 端口。运行时只需要静态文件服务器。

## 替换个人信息

- `name`、`affiliation`：姓名和学校信息。

## GitHub Pages 免费发布

项目包含 `.github/workflows/deploy-pages.yml`。推送到 `main` 后，GitHub Actions 会安装依赖、构建静态网站并发布；也可以在 Actions 页面手动运行。

首次发布需要在 GitHub 仓库中启用 Pages：

1. 打开 `https://github.com/jinran0210/jinran0210ye/settings/pages`。
2. 在 **Build and deployment → Source** 选择 **GitHub Actions**。
3. 打开仓库的 **Actions** 页面，选择 **Deploy personal website to GitHub Pages**，点击 **Run workflow**，选择 `main`。
4. 两个任务 **Build website** 和 **Publish website** 成功后，查看 Pages 设置中给出的网址。

预期网址为 `https://jinran0210.github.io/jinran0210ye/`，需以 GitHub 的部署结果和实际访问为准。GitHub Free 的 Pages 需要公开仓库；如果仓库是私有的，请先检查账号方案和仓库设置，不要为了部署直接改动仓库可见性。

发布构建命令：

```sh
npm run build:pages
```

这个命令会设置 `/jinran0210ye/` 子路径，确保插画、图标和脚本在 GitHub Pages 上正常加载。未来修改 `src/profile.js` 并推送到 `main`，会自动更新网站。工作流只使用 GitHub 提供的临时令牌，无需在代码或仓库 Secrets 中添加个人令牌。

## 其他静态网站平台

可将项目部署到支持静态网站的平台（例如 Cloudflare Pages、Netlify 或 Vercel）：

- 构建命令：`npm run build`
- 输出目录：`dist`
- Node.js：22.12 或更新版本

若使用独立域名或用户名根站点，使用默认构建即可。构建和本地验证本身不会发布到公网；GitHub Pages 工作流的成功结果才表示 GitHub 部署完成。
